# LARP

A macOS menu bar app that records calls (microphone and system audio), transcribes them on the Mac and keeps an archive. Everything stays on the Mac: no cloud, no account, no telemetry. The interface is in Italian.

Requirements: an Apple silicon Mac (M1 or later) with macOS 26 or later, and Xcode.

## Install XcodeGen

The Xcode project is generated from `project.yml` and is not committed.

```sh
brew install xcodegen
```

## Generate the project

```sh
xcodegen generate
```

Run it again whenever `project.yml` changes. Source files under `Sources/LARP/` are picked up automatically; new files do not need `project.yml` edits, but the project has to be regenerated to show them in Xcode.

## Build and run

From Xcode: open `LARP.xcodeproj`, select the `LARP` scheme and press Run.

From the command line:

```sh
xcodebuild -project LARP.xcodeproj -scheme LARP -configuration Debug -derivedDataPath build build
open build/Build/Products/Debug/LARP.app
```

The app has no Dock icon: look for the microphone icon in the menu bar.

Builds are ad-hoc signed and not notarized. To sign with a personal team instead, set in `project.yml` `CODE_SIGN_STYLE: Automatic`, `CODE_SIGN_IDENTITY: "Apple Development"` and `DEVELOPMENT_TEAM: <team id>`. With a stable signature macOS keeps the microphone and system audio permissions across rebuilds.

## Tests

Tests use Swift Testing and live in `Tests/LARPTests/`; new files there are picked up automatically (`project.yml` does not need edits, regenerate the project to see them in Xcode). They run inside the app, so use `@testable import LARP`.

```sh
# all tests (what CI runs)
xcodebuild test -project LARP.xcodeproj -scheme LARP -destination 'platform=macOS,arch=arm64' -derivedDataPath build

# a single suite or test
xcodebuild test -project LARP.xcodeproj -scheme LARP -destination 'platform=macOS,arch=arm64' -derivedDataPath build \
  -only-testing:LARPTests/ArchiveStoreTests
xcodebuild test ... -only-testing:LARPTests/ArchiveStoreTests/deleteCascades
```

Tests that need Apple speech models, FluidAudio models, the microphone or system audio must carry the tag `.requiresHardware` (`@Test(.tags(.requiresHardware))`, defined in `Tests/LARPTests/Tags.swift`). The test plan `Tests/LARP.xctestplan` skips that tag, so they do not run in CI or from the command line; run them from Xcode by disabling the tag filter of the plan.

## Releases

`.github/workflows/release.yml` publishes a version as a GitHub Release of the private repository. Distribution is limited to the developer's Macs and a few trusted people with read-only access to the repository: there is no public channel.

To publish a version, push a tag `vX.Y.Z`:

```sh
git tag v1.2.0
git push origin v1.2.0
```

On a `macos-26` runner the workflow generates the project, runs the same tests as the CI (a failing test stops it before anything is published), builds the Release configuration (ad-hoc signed, not notarized) and creates `LARP-1.2.0.dmg` with `hdiutil`. The DMG contains `LARP.app` and a link to `/Applications`. The Release is named after the tag, has the DMG attached, and its text (in Italian) is followed by the notes generated by GitHub. `MARKETING_VERSION` is set to the tag without the leading `v` and `CURRENT_PROJECT_VERSION` to the workflow run number, both at build time: `project.yml` is not edited.

To install a version, download `LARP-<version>.dmg` from the Release, open it and drag `LARP.app` to Applications. The app is not notarized, so macOS blocks the first launch. Open it with either:

- `xattr -dr com.apple.quarantine /Applications/LARP.app`, then launch the app;
- or launch the app, then open System Settings → Privacy & Security and click "Open Anyway".

Updates are manual: download the new version and replace `LARP.app`. The app does not check for updates and contacts no update service. After every update macOS asks again for the microphone and system audio permissions.

## Continuous integration

`.github/workflows/ci.yml` runs on every push and pull request on a `macos-26` runner: it installs XcodeGen, generates the project, builds and runs the tests.

## Layout

```
project.yml            XcodeGen project definition
Config/                Info.plist and entitlements (generated by XcodeGen from project.yml)
Sources/LARP/App/      App entry point, menu bar menu, archive window
Sources/LARP/Model/    SwiftData archive (Call, TranscriptLine, Participant), paths, store
Sources/LARP/Settings/ Settings scene and UserDefaults keys
Tests/LARPTests/       Swift Testing tests (tag .requiresHardware = not run in CI)
Tests/LARP.xctestplan  Test plan: skips the .requiresHardware tag
.github/workflows/     CI (ci.yml) and release (release.yml) workflows
```

Data lives in `~/Library/Application Support/LARP/`: the SwiftData store (`LARP.store`) and one `Recordings/<call id>/` folder per call with `mic.caf` and `system.caf`.

## Dependencies

Swift Package Manager only. The single third-party dependency is [FluidAudio](https://github.com/FluidInference/FluidAudio), pinned in `project.yml`.
