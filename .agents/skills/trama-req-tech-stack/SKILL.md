# Requirements: Technology and constraints, Stack and platform APIs

Generated by Trama from `.trama/requirements/tech/stack.md`. Do not edit this file: change the Requirements through a Trama Proposal (or ask the developer).

These are the developer's Requirements for how the System is built. Follow them when you write code. The Model (`.trama/model/`) says what the System does; when a Requirement and the Model disagree, stop and tell the developer.
A section titled with a Model reference (such as `order/Paid`) applies to that element and to everything inside it.

## General

- Native macOS app in Swift 6 with strict concurrency and SwiftUI; minimum deployment target macOS 26.0; built for Apple silicon (arm64) only.
- The Xcode project is generated by XcodeGen from a versioned `project.yml`; the generated `.xcodeproj` is not committed.
- The app is a menu bar app (`MenuBarExtra`) with a separate archive `Window` and a `Settings` scene; it has no Dock icon (`LSUIElement`).
- The app is not sandboxed and is signed ad-hoc (local builds may use the developer's personal team instead); no notarization.
- Info.plist declares `NSMicrophoneUsageDescription` and `NSAudioCaptureUsageDescription` with Italian texts explaining that call audio stays on the Mac.
- Swift Package Manager is the only dependency manager; the only third-party dependency is FluidAudio.
- No cloud service, no account, no telemetry.
- Distribution is limited to the developer's Macs and a few trusted people, who are read-only collaborators of the private GitHub repository and download the app from its GitHub Releases; no public distribution.
- A GitHub Actions release workflow, separate from the CI workflow, runs on every tag `vX.Y.Z`: it runs the test plan as CI does and publishes only if the tests pass, then builds the Release configuration, ad-hoc signed, without notarization.
- The released version comes from the tag: the workflow sets `MARKETING_VERSION` to the tag without the leading `v` (`v1.2.0` → `1.2.0`) and `CURRENT_PROJECT_VERSION` to the workflow run number at build time; `project.yml` is not edited to release.
- The app is packaged as a plain DMG created with `hdiutil`, holding `LARP.app` and a link to `/Applications`, with no background image or custom layout, named `LARP-<version>.dmg` and attached to a GitHub Release named after the tag.
- The Release text is in Italian: it explains how to install the app (drag `LARP.app` to Applicazioni), how to open an app that is not notarized (`xattr -dr com.apple.quarantine /Applications/LARP.app`, or "Apri comunque" in Impostazioni di Sistema → Privacy e sicurezza), and that macOS asks again for the microphone and system audio permissions after every update; GitHub's generated release notes follow it.
- Updates are manual: the user downloads and installs the DMG of the new version; the app never checks for updates and contacts no update service.
- The README documents in English how to publish a release (push a `vX.Y.Z` tag) and how to install and open the downloaded app.

## recorder

- Detection of call apps uses the Core Audio process object list (`kAudioHardwarePropertyProcessObjectList`) and each process's `kAudioProcessPropertyIsRunningInput` and bundle identifier, listening for changes instead of polling; helper processes (for example browser helpers) are mapped to their parent app.
- The microphone is captured with `AVAudioEngine` on the default input device.
- The system audio is captured with a Core Audio process tap (`CATapDescription` for all processes except LARP itself, `AudioHardwareCreateProcessTap`, aggregate device), which needs only the system audio recording permission, not screen recording.
- Permissions are checked before every start: microphone with `AVAudioApplication`/`AVCaptureDevice` authorization, system audio by the tap creation result.

## call

- Transcription uses `SpeechAnalyzer` with one `SpeechTranscriber` per track (microphone and system audio), configured with the chosen language and volatile plus final results with audio time ranges; only final results are stored.
- Audio is converted to `SpeechAnalyzer.bestAvailableAudioFormat(compatibleWith:)` before being fed to the analyzer.
- Live transcription runs off the main actor and must never block audio capture: audio is written to disk first, then fed to the analyzer.

## call/Separating participants

- Speaker separation uses FluidAudio's offline diarization (`DiarizerManager` or its successor in the pinned version) on the system audio track resampled to 16 kHz mono; the number of speakers is detected automatically.
- Each "Others" line goes to the participant whose diarization segments overlap it most in time; a line without any overlap goes to the participant of the nearest segment.
- FluidAudio models are downloaded on first use into the app's Application Support folder and reused afterwards.

## transcription-language

- Installation of the speech model uses `AssetInventory` (`assetInstallationRequest(supporting:)` for the `SpeechTranscriber` of the chosen locale); whether a locale is installed comes from `SpeechTranscriber.installedLocales`.
- Supported choices map to the locales `it-IT` (Italian) and `en-US` (English).

## settings

- Launch at login uses `SMAppService.mainApp`.
