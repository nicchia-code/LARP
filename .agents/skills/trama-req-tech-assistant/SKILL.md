# Requirements: Technology and constraints, Assistant (omp)

Generated by Trama from `.trama/requirements/tech/assistant.md`. Do not edit this file: change the Requirements through a Trama Proposal (or ask the developer).

These are the developer's Requirements for how the System is built. Follow them when you write code. The Model (`.trama/model/`) says what the System does; when a Requirement and the Model disagree, stop and tell the developer.
A section titled with a Model reference (such as `order/Paid`) applies to that element and to everything inside it.

## assistant-status

- omp is looked up at every check, every refinement and every summary through the user's login shell (`$SHELL -l -c 'command -v omp'`), because apps opened from the Finder do not get the shell's `PATH`.
- omp is started with `Foundation.Process` as `omp acp`, with built-in tools disabled and no saved session when omp accepts the options (`--no-tools`, `--no-session`), in a new empty temporary folder used as working directory and deleted afterwards.
- The Agent Client Protocol (JSON-RPC 2.0, one message per line on standard input and output) is spoken directly by the app, without a new package dependency.
- The app declares no file system and no terminal capability in `initialize`, refuses every `session/request_permission`, uses the credentials already configured in omp and never chooses a model: omp uses its default model.
- The check starts omp, sends `initialize` and ends the process: an answer within 10 seconds means the assistant is reached; no omp found, an error or no answer in time means it is unreachable.

## call/Refining transcript

- Refinement runs off the main actor and never blocks the interface or a recording.
- Each refinement starts its own `omp acp` process as described in `assistant-status`, opens one session with `session/new` and sends one `session/prompt`: fixed instructions saying what the assistant may correct, followed by the lines as JSON (`number`, `speaker`, `start`, `end`, `text`).
- The instructions ask for an answer made only of JSON, one object per line with `number`, `text` and `speaker`; the text of the answer is gathered from the `session/update` messages until the prompt ends.
- The 10-minute limit counts from the start of the process; when it passes, the process is terminated and the refinement fails.
- Turning refinement off or deleting the call terminates the running process at once.
- A valid answer is applied to every line in a single save, keeping the original text and speaker of every line; nothing is saved from an answer that is not valid.

## call-summary

- Writing a summary runs off the main actor and never blocks the interface, a recording or the refinement of the same call: refinement and summary of one call can run at the same time, each with its own `omp acp` process.
- Each summary starts its own `omp acp` process as described in `assistant-status`, opens one session with `session/new` and sends one `session/prompt`: fixed instructions saying what the summary holds and in which language to write it, followed by the lines as JSON (`number`, `speaker`, `start`, `end`, `text`).
- The instructions ask for an answer made only of one JSON object with `keyConcepts` (list of strings), `decisions` (list of strings), `nextSteps` (list of objects with `text` and an optional `owner`) and `other` (string, possibly empty); the text of the answer is gathered from the `session/update` messages until the prompt ends.
- The 10-minute limit counts from the start of the process; when it passes, the process is terminated and the summary fails.
- Turning call summaries off or deleting the call terminates the running process at once.
- A valid answer is saved in a single save, replacing any earlier summary of the call; nothing is saved from an answer that is not valid, and the earlier summary stays.
